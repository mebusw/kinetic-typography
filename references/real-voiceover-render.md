# 真人口播 + 真人露脸：从实录到成片

> 这个文件记录的是 `real-voiceover.md` 之后的那一步——**把收紧后的实录变成一条真的能发的片子**。
> 每一条都是踩出来的，不是设计出来的；每条都写明"错的时候它长什么样"。

---

## 1. 收紧：最贵的一刀是片头

### 规则

**只有当静音区真的贴着文件边缘时才剪它。**

```python
# 错：把"第一处静音"当成片头
if gaps and gaps[0][0] > 0.35:
    cuts.insert(0, (0.0, gaps[0][0] - head_pad))
# 对：静音必须从 0 附近开始
if gaps and gaps[0][0] <= 0.05 and gaps[0][1] > head_pad:
    cuts.insert(0, (0.0, gaps[0][1] - head_pad))
# 尾同理：静音必须结束在文件末尾
if gaps and dur - gaps[-1][1] <= 0.05:
    cuts.append((gaps[-1][0] + tail_pad, dur))
```

### 它错的时候长什么样

`silencedetect` 报的第一处静音**通常在第一句中间**——说话人换气的地方。
三支实录的第一处静音分别在 6.2s / 2.6s / 5.5s，而开口第一句分别长 6.4s / 5.8s / 5.9s。
于是整句被剪掉。**成片完全能播、时长对得上、没有任何报错**，只是每一集都缺了开场那句。

### 自检（写进流程，不要靠眼睛）

打完点后逐句打印 `首句起始时间` 与 `收紧后总长`，确认：

- 首句的 `end - start` 与原始转写的同名句一致（±0.3s）；
- 末句同理；
- **五支里只要有一支首句时长接近 0，就是中招了。**

实测收紧比例 7.5%–13%（同一个人不同集的语速差异）。低于 5% 通常意味着根本没在剪。

## 2. 音效落点：锚在词上，不是手填秒数

手填的绝对秒数在**重打点之后会集体错位**，而且错得非常安静——音乐照响，画面照动，
只是每个"盖章音"都落在半句话中间。

做法：把词级转写拼成一条去掉标点的长串，落点写成"短语 + 增益"，
生成音频时再解析成绝对时间。重新打点只需要改分段表，落点自动跟着走。

```python
def at_word(tag, phrase):
    ws = words(tag)                       # 词级转写
    flat, times, offs = '', [], []        # offs[i] = 第 i 个词的起始字符
    for w in ws:
        t = norm(w['w'])                  # 去掉标点与空白
        if not t: continue
        offs.append(len(flat)); flat += t; times.append(w['s'])
    k = norm(phrase)
    i = flat.find(k)                       # 找不到就抛错，不要静默跳过
    if i < 0: raise KeyError(phrase)
    wi = max(j for j, o in enumerate(offs) if o <= i)   # 字符下标 → 词下标
    return round(times[wi], 2)
```

**两条配套纪律**：

1. **先批量校验所有锚点，再写进音频脚本**。ASR 的词级输出与句级输出不一致
   （同一句在句级被订正过、词级还是原样），锚点要按**词级那份**写。
2. 锚在**不会错的那部分**上：数字、产品名、专有名词最容易被 ASR 切碎或写错，
   锚在它周围的动词或短语上。

## 3. 音轨：HyperFrames 装配时会做一次动态处理

**实测：成片比母带高 3.0 dB 积分响度，真峰几乎不变**（02–06 五支一致）。
所以母带的 loudnorm 目标要倒过来写：

```
母带目标 I = −22 LUFS / TP = −2.5 dBFS  →  成片落在 −19 LUFS
```

**为什么这条必须知道**：成片响度是唯一的"这一支到底用了哪条音轨"的判别信号。
按 −19 出母带，成片就是 −16，正好落在口播带外，而**所有静态检查都是绿的**。

流程固定为：

```
床（低频重心抬到 150Hz 以上）→ RMS 对齐口播 −20dB → 侧链只压床与音效
→ peak 归一化 → 软拐点饱和 → 两遍 loudnorm(-22, linear=true) → alimiter
```

侧链别用手写的包络卷积去压人声——那会把语音的动态也吃掉。用 `ducking` + RMS 对齐就够。

## 4. 真人头像：圆形蒙版的六个细节

Zoom 录的横屏素材，裁成 1:1 正方形再用 CSS `border-radius` 切圆。
**不要用带 alpha 的 webm**——没有 alpha 通道的编码器会静默丢掉透明平面，
你得到一个不透明的方块。

| 细节 | 值 / 做法 |
|---|---|
| 裁切 | `crop=640:640:320:0`（源 1280×720，取正中 640 见方） |
| 尺寸 | 320px 直径，约占短边的 1/3 |
| 位置 | 右下 `x = 706, y = 1512`——**压在录屏演示区的下方**，不是叠在上面 |
| 描边 | `box-shadow: 0 0 0 4px <底色>, 0 0 0 7px <强调色>` |
| 浅底主题 | 描边的第一圈必须用**底色**；`mix-blend-mode` 从 `screen` 换成 `multiply` |
| 进度条 | 宽度要减去头像槽位，否则一条线从头像里穿过去 |

头像视频和主口播**必须来自同一条收紧后的时间表**。头像单独剪一次，唇动就会和声音差半拍——
这是这一类片子最容易被观众察觉、又最难用耳朵指认的错误。

## 5. 框架契约：四个属性缺一个就整片全黑

```html
<div id="root" data-composition-id="main" data-start="0"
     data-duration="91.6" data-width="1080" data-height="1920">
```

**缺了 `#root` 上的这四个属性，渲染器会按 0 帧处理：出片时长对、分辨率对、帧数对，
每一帧都是黑的。** 所有静态检查全绿，因为它们检查的是生成器写的文件，不是渲染器的行为。

同一类"静默失败"还有两处：

- **背景层必须放在 DOM 最前面**。同层级下 DOM 顺序 = 绘制顺序，
  整屏 `.bg` 追加到末尾会盖住所有内容——`getComputedStyle` 一切正常，画面全黑。
- **`data-duration` 必须等于"入场开始 → 退场开始"的窗口**，不是入场动画的时长。
  框架按这两个属性判断"这段时间元素存不存在"；只填入场时长，
  元素会在真正停留的那几秒里被判为不存在（画面上整段消失）。

## 6. 遮挡检查读的是哪个元素，就必须是哪个元素被动画

`check_occlusion.mjs` 用 `getComputedStyle(el).opacity` 判断可见性，读的是**元素自己**。
父级 `opacity:0` 对它不可见。于是：

```
<div class="at" style="opacity:0">      ← 动画挂在这里
  <div class="shell">…</div>            ← 检查器读这个 → 永远 opacity:1
</div>
```

**每一张卡都会被判成"常驻可见"，报告里全是幽灵重叠。**
把 `.at` 和语义类（`.shell` / `.lead` / `.ctabox` / `.bignum`）放在**同一个元素**上：

```html
<div class="at shell" id="cd" data-start="52.9" data-duration="10.7" …>
```

## 7. 零尺寸元素会被渲染成贯通全屏的条

自绘连接线时留了 `height:auto`。DOM 里量出来是 `0`，快照里完全看不出来，
**成片里是两条从方块一路画到画面底边的亮色竖条**。

> 空 div 在渲染器里的绘制区域不等于 `getBoundingClientRect()`。

**规则：每一个装饰件都要写死 `width` 和 `height`。** 画连接线也一样，
`height:4px` 和 `height:auto` 在这里不是一个意思。

## 8. 段头：只动子元素会留下一整段看不见的段头

```js
// 错：父级 .at 是 opacity:0，子元素怎么动都没用
tl.fromTo('#n', {opacity:0,x:-22}, {opacity:1,…})
// 对：整体淡入，子元素只动 transform
tl.fromTo('#w', {opacity:0}, {opacity:1,duration:.4}, c.start)
tl.fromTo('#n', {x:-22}, {x:0,duration:.5}, c.start)
```

## 9. 渲染：两个"进程活着但没在干活"

**(a) 渲染进程被 pty 挂成停止态。** `ps` 显示 `STAT` 为 `T`，没有报错、没有输出，
文件也不长大。修法是让 shell 忽略终端的停止信号：

```sh
trap '' TTIN TTOU
exec npx --yes hyperframes@… render …
```

**(b) `p.evaluate(() => tl.seek(t))` 会挂死。** `seek()` 返回 timeline 自身，
CDP 会去序列化一个带 DOM 引用的大对象图。**必须用块体**：

```js
await p.evaluate((tt) => { window.__timelines['main'].seek(tt); }, t);   // ✅
await p.evaluate((tt) => window.__timelines['main'].seek(tt), t);      // ❌ 挂 120s
```

**快照必须挡掉 media。** `setRequestInterception` + `abort()` 掉
`.mp4/.webm/.wav`，软件解码就不会把主线程拖死。挡掉之后每帧 seek 是毫秒级；
不挡的话同一支片子时快时慢，没有规律。

## 10. 浅底（浅色）主题

放到系列最后收口用。四个必须改的地方：

- 卡片背景从 `rgba(0,0,0,.55)` 阴影换成更轻的投影，卡内底色改成 `#fff`；
- 头像外描边第一圈用底色，不要用黑色；
- 强调色必须换——深底上的亮色（洋红、青柠）在浅底上会发灰，朱红/砖红这一类才成立；
- `mix-blend-mode: screen` 在浅底上会把头像洗白，换 `multiply`。

## 11. 裁剪参数写的是源坐标

```
ffmpeg -i src.mov -vf "crop=W:H:X:Y,scale=-2:720" out.mp4
```

`crop` 在 `scale` 前面，**用的是源分辨率坐标**。把缩放后的坐标填进去，
ffmpeg 会报 `Invalid too big or non positive size`——
或者更糟：不报错，直接裁出另一段内容。

竖屏录屏（源 1410×1614 / 1234×1526）直接铺进 16:9 的卡里会有大片空白，
裁掉上下留白这一步是必须的：先量源里"有内容"的那一段，再按源坐标裁。

## 13. 删除内容：语音和画面必须一起删

合规性删除这类修订，删除窗口要和停顿压缩写在同一次里，而且必须写在**原始素材时间轴**上，而不是收紧后的时间轴。写错了会切在完全无关的地方。

删掉一段之后的重打点很省事：**连续删除就是一次纯平移**，窗口之后的所有时间减去窗口长度，段内相对时间一个字都不用改。只有被窗口切开的那一段需要重新划边界。

### 转写要按存活过滤，不是按时间映射

把每句源码段映射过 keep 区间之后，**落在被删窗口里的句子会被夹到边界上，仍然留在转写里**。结果是一份看起来根本没剪过的文稿。判据要用**区间求交**，不要拿中点去测。

交集为空就丢掉这句话；两侧都被削等于只剩半句，也丢掉；短于 0.35s 的残句同样丢掉。**做完这一步之后逐句打印首句与末句，人眼过一遍**——这是唯一能确认删干净的动作。

### 验证

改完之后同时查两处，缺一不可：画面搜 `proj/index.html`，语音搜 `vo_final_segments.json`，品牌词与安装字样一律应为 0。只查画面会漏掉"说了但没放"；只查转写会漏掉"放了但没说"。

## 14. 版面：两行字要显式高度，右侧要断言边界

- **两行标签**：默认框高是「字号 + 30」，正好只放得下一行。第二行会顶出边框被裁掉，而四项遮挡检查全绿——它量的是卡片框和人头框，不是文字框。框高按内容算，不按字号算。
- **右边界**：挂在右边的元素（本系列的轴线在 x=986），一旦给它一个 460 宽的条，整条就越出画面 366px。元素照样在 DOM 里、照样能被量到、检查器照样报"存在"。断言 x + w 不超过「画幅宽 − 边距」；能用左边距对齐的左栏，就不要挂在右边的脊柱上。
